## Session — 运行期瓶颈处置边界

**What happened:** 用户认可 Agent 在运行中发现新瓶颈后立即呈现证据与交付风险，并在既有授权内处置。

**Key outcomes:**
- 新瓶颈可先作为运行事实被观察和处理，不必等待长期模型变更。
- 固化进价值流模型或改变长期策略，须价值流负责人确认。

**Follow-up:** 澄清识别信号与可信度、授权内动作、何时建议长期固化，以及模型变更的追溯。

**Strategy ownership:** 用户确认企业经营者设统一权限和风险规则，价值流负责人配置本流处置方式，Agent 运行时按瓶颈与风险选择授权内动作。

**Flow control:** 用户允许 Agent 在负责人预设范围内暂缓上游新工作进入积压环节，并在缓解后恢复；入口边界、恢复阈值和承诺例外待定义。

**Selective release:** 用户允许已承诺且高失约风险的工作项按预设规则例外进入；其对其他承诺的影响、容量上限和多个例外的排序仍待定义。

**Risk coverage:** 用户希望风险处置覆盖交付失约、质量、成本与合规；尚需明确跨风险优先级和不可越过的门禁。

**Product philosophy pivot:** 用户明确场景 Agent 协作网络是 XPS 主体，Agent 核心执行，人负责确权、责任、策略与决策／批准；Lab 围绕 Agent 组涌现方案做沙盒参照组比对。已建立 Q-20261015-001 和产品理念讨论稿；实验方案进生产的批准权未定。

**Decision elements:** 用户要求知识、数据、能力共同驱动 Agent 生产与决策，有统一可迭代的组织语义网络；跨 Agent 共享与 Agent 自有边界未决，已建立 Q-20261015-002。其“动态本体”限制原话有歧义，需澄清。

**Layered sharing confirmed:** 用户认可共同语义、受控共享资源及 Agent 自身专业配置和任务状态的分层模型；知识晋升、语义迭代和细权限待讨论。

**Knowledge promotion:** 用户确认 Agent 新经验经运行或 Lab 效果验证后，须价值流负责人确认才成为场景共享知识；组织级语义迭代尚待定义。

**Semantic governance:** 用户认可 Agent／价值流负责人可提议跨场景语义变更，企业指定语义责任人确认后进入组织共用网络；版本与回滚待定义。

**Semantic role:** 用户确认语义网络统一概念与关系，Agent 根据知识、数据、能力、策略和授权决定执行；语义网络不逐步驱动动作。

**Lab promotion:** 用户确认单场景 Agent 组合／策略由价值流负责人批准推广，跨场景语义／企业级规则由对应企业级责任人批准；评价、灰度与回滚待定义。

**Scope narrowed:** 用户明确当前阶段以场景价值流为独立构建单元，数量未限定；运行节拍与场景内 Lab 的本阶段交付时点待确认，跨场景能力及治理后置。已同步收束理念稿和业务／产品视图。

**Real-item validation:** 用户要求用一个实际工作项跑通构建的场景价值流并验证；最小执行／验收链进入本阶段，Lab 交付时点仍待定。

**Pilot selection:** 用户认可平台 Agent 引导价值流负责人挑选覆盖 Agent 执行、必要人工决策和最终验收证据的真实工作项。

**Construction order:** 用户确认先定义可验收业务结果与完成事件，再由 Agent 梳理工作项、参与者、知识／数据／能力与授权，最后以真实工作项验证。

**Network draft:** 用户同意平台 Agent 根据价值流生成 Agent 分工与协作关系初稿，价值流负责人修正并确权后用于试点。

**Capability gap:** 用户要求平台 Agent 在现有 Agent 不足时生成新 Agent 候选，列明知识、数据、能力、权限并交负责人确认；启用前如何验证待定。

**Agent enablement:** 用户确认候选确权后须通过场景内样例任务验证能力、数据使用与授权，才能进入真实工作项；具体标准与失败回修待定义。

**Pilot rework:** 用户要求真实工作项验收失败时，Agent 基于证据定位模型、能力、数据或授权问题，提出修订草案，负责人确认后重验。
