# XPS 产品理念（当前阶段讨论稿）

首阶段功能清单与工作台流程见 [first-phase-features-and-workbench.md](first-phase-features-and-workbench.md)。

## 一句话定义

XPS 是围绕具体业务场景构建价值流、Agent 与人协作网络，并驱动工作项执行的企业平台。Agent 是核心执行主体；人负责为 Agent 确权，承担业务责任，设计策略，并在需要时作出决策和批准，也可以承担执行任务。平台通过运行中的瓶颈与风险处置，以及 Lab 中的沙盒对照实验，持续改善场景业务效果。（S-033～S-035、S-057；节拍与瓶颈见 S-025～S-032）

## 三个关联维度

| 维度 | 表达什么 | 当前已确认的主体与关系 |
|---|---|---|
| 业务价值流 | 业务目标、价值如何流动、作为承载点的业务成果与状态，以及验收边界 | 由业务结果出发构建，作为场景的价值骨架（S-047、S-057、S-059） |
| 协作网络 | 围绕价值流组织 Agent 与人的组合，保障价值交付 | Agent 为核心执行主体，人承担确权、责任、策略、必要的决策与执行（S-034、S-057） |
| 任务执行 | 具体工作项如何拆解、分派和执行 | 按工作项动态形成任务，执行主体可以是 Agent 或人（S-052、S-057） |

产品化归纳（待细化）：一个工作项沿价值流推进；协作网络为其价值承载点提供参与主体与协作关系；执行任务产生交付物及验收证据。三个维度需要关联，但不采用同一种节点模型表示。此前提出的“职责节点”只能作为协作关系的一种描述，不能代替完整的价值流或任务模型。

价值承载点具体指业务成果与状态（S-059）。产品化归纳：价值流可用这些成果／状态及其流转关系表达业务推进；协作主体和执行任务分别关联到相应成果／状态，而不成为价值流节点本身。流转、分支与返工规则待讨论。

业务价值状态（如“需求已确认”）属于价值流；等待、阻塞和失约风险属于工作项运行状态，应投影到价值流以显示价值停滞的位置和时长（S-060）。具体状态事件与瓶颈阈值待定义。

一个工作项可同时推进多个业务成果／状态，价值流因此须容纳并行路径（S-065）；各路径何时汇合、需要哪些验收证据，仍待定义。

并行路径的汇合门由场景蓝图定义：必备成果、按条件择一或豁免的成果，以及进入下一业务状态的条件。Agent 在这些条件内动态安排分支任务；临时修改汇合条件须经价值流负责人确认（S-066）。具体表达、豁免证据与运行中版本影响待定义。

AI 节拍的核心判断是在并行路径中识别真正制约汇合门与最终验收的分支，综合承诺剩余时间、失约风险，以及质量、成本、合规风险决定协调重点，而不只按等待时长排序（S-073）。预测依据、风险权衡和动作效果验证待定义。

每次协调形成关联工作项的**节拍决策记录**：汇合门、已确认承诺及其剩余时间（如有）、各分支预测及风险、可选动作、Supervisor 所选动作及授权依据、执行后的结果；有依据的暂不干预也需记录（S-077）。尚未形成客户承诺时标明该状态并保留 Agent 预测（S-072）。具体生成、回看与修订规则待定义。

场景级协作网络由价值流负责人确认，作为可复用的 Agent／人协作结构；具体工作项运行时可动态选择参与者、拆解及转派任务。若要长期改变协作结构，由负责人确认新版本（S-058）。

场景内的 AI 节拍协调需支持 **Supervisor 模式**和**群体协调模式**两种形态（S-061）。前者由场景级协调 Agent 主导，后者由多个 Agent 分担协调；两种模式的职责分配、权限与切换规则待定义。无论采用哪种模式，价值流目标、授权边界、冲突确认和运行证据均应可追溯；这是基于既有原则的产品化归纳。

同一场景可设默认协调模式，并对具体价值承载点配置另一种模式（S-062）。工作项跨承载点推进时，模式间的交接与运行中临时切换规则仍待定义。

群体协调模式下，任一有权限的 Agent 可根据瓶颈或风险提出调度动作；受影响的 Agent 与人反馈能力、责任和风险。符合规则且无冲突时直接执行；出现冲突时由 Agent 推进协商，交决策管理员确认后生效（S-063；既有冲突门禁见 S-007～S-010）。

Supervisor 模式下，参与 Agent 向 Supervisor Agent 报告瓶颈、风险与建议；Supervisor 汇总后在预授权内选择并下达调度动作。受影响方可反馈冲突；冲突方案仍需决策管理员确认（S-064）。两种模式共用授权、风险与冲突门禁，区别在调度动作的发起和形成路径。

### 场景产品模型 v0（产品化归纳，供后续讨论）

| 对象 | 最小含义 | 关键关联 |
|---|---|---|
| 场景价值流 | 目标、业务成果／状态承载点及其流转、验收门与并行汇合条件 | 承载点可指定协调模式；门关联证据与授权 |
| 协作网络 | 围绕价值流的 Agent 与人、协作关系和可用权限 | 场景级版本经负责人确认；主体可参与多个承载点 |
| 工作项 | 一次实际业务需求到成果验收的实例 | 关联价值流版本、可并行推进的多个业务成果／状态、交付承诺与运行状态 |
| 执行任务 | 工作项内动态拆解和分派的动作 | 关联要推进的成果／状态、实际执行者与交付物 |
| 协调动作 | 面对瓶颈、等待或风险的提案、反馈、调度与升级 | 关联当前模式、策略／授权、受影响方和决议记录 |
| 验收证据 | 支撑阶段门与最终业务结果判断的材料和核验记录 | 关联来源、目标／门、执行任务及有权验收者 |

产品运行的最小链：工作项进入价值流 → Agent 按具体情况拆解任务 → Agent／人协作执行 → 运行状态投影到价值流 → 所在承载点按 Supervisor 或群体模式协调 → 验收门依据证据与授权放行或交人 → 最终结果验收。对象字段、关系基数和状态机仍待定义。

工作项状态宜按不同维度分别呈现（产品化归纳）：**业务价值进度**记录可并行推进的成果／状态；**运行状态**记录等待、阻塞与风险；**交付时间**区分 Agent 预测和负责人确认的客户承诺；**受理与验收**记录建项来源及最终确认。它们可以同时变化，避免用一个总状态掩盖并行、风险或承诺边界（基于 S-016、S-060、S-065、S-071、S-072）。

### 首个产品使用路径（产品形态推演，待确认）

1. 价值流负责人描述业务结果、完成事件及定量／定性验收条件；平台 Agent 追问缺失的判据。
2. 平台 Agent 生成由业务成果／状态组成的价值流草案，标出并行路径、汇合条件、验收门、候选瓶颈与证据要求；负责人修订和确认。
3. 平台 Agent 围绕价值承载点生成 Agent／人协作网络，建议默认与局部协调模式、知识／数据／能力、授权及备选执行者；负责人确权，新 Agent 经样例验证。
4. 负责人选择真实工作项。Agent 动态拆解、分派与执行任务；平台在价值流上显示已形成成果、等待／阻塞、风险、协调动作和验收证据。
5. 工作项达到最终验收门后按目标性质和授权完成验收。失败时 Agent 依据证据提出蓝图或网络修订，负责人确认新版本后重验。

以上是基于 S-044～S-066 的产品化组合；界面布局、自动生成质量与首阶段交付粒度尚未确认。

场景构建采用“平台 Agent 对话引导 + 可编辑图”的入口：平台生成价值流图与 Agent／人协作网络图，价值流负责人直接在图上修订；真实工作项运行后展示任务、风险与证据（S-067）。对话与图编辑如何同步、哪些变更需要重新确权，仍待设计。

协作网络图首版以交付物交接、共同协作、授权与决策、替补与升级四类关系为核心候选（S-068），并加入状态／风险的观察与反馈关系（S-069）。Agent 本身需能接收外部通知消息（S-069）。通知的来源可信度、具体工作项映射和异常处理待定义。

外部通知既可定向投递给指定 Agent，也可由 Agent 按场景事件类型订阅。Agent 收到通知后确认来源、关联工作项，再依据已有授权判断是否行动；通知本身不授予执行权（S-070）。身份校验与去重规则待定义。

通知若无法关联现有工作项，Agent 可在来源可信、场景归属明确且满足预设受理规则时，在 XPS 自动创建新工作项；判断不明确则交价值流负责人，保留原通知供追溯（S-071）。去重、初始状态与受理规则细节待定义。

规则内自动建项后，Agent 可立即开展授权范围内的准备和执行。完成时间先作为 Agent 预测；价值流负责人确认后才构成对客户的交付承诺（S-072，承诺权限见 S-016）。建项、执行与承诺分别留痕，承诺前的可执行范围待细化。

## 当前阶段范围

以**场景价值流为独立单元进行构建**：定义业务结果与工作项，组织参与的 Agent 与人，明确所需的知识、数据、能力、策略和授权（S-044）。本阶段至少选择一个试点场景及一个真实工作项，由 Agent 网络实际推进并留下验证证据（S-045）。可构建多少条场景价值流尚未限定；本阶段不定义它们之间的协作。Lab 保留在 XPS 产品理念中，本阶段交付时点待确认。

试点工作项由平台 Agent 引导价值流负责人选择，验证覆盖 Agent 实际执行、该工作项所需的人工决策及最终验收证据（S-046）。

首个试点还应包含并行成果与汇合门，并至少留下一次 Agent 对分支风险的判断及协调选择记录；选择可以是有证据的暂不干预（S-074）。这验证节拍判断链实际运行，不以单个工作项宣称周期或预测绩效已改善。

首个真实工作项先跑通 **Supervisor 模式**（S-075、S-076），无须同时经过群体协调模式。后者如何验证及跨模式交接何时验收，仍待确定。

### 首个试点验收约定（基于已确认原则的整理）

| 验证项 | 应留下的证据 |
|---|---|
| 场景蓝图可用 | 经负责人确认的业务结果、至少两条并行成果路径、汇合门与验收条件 |
| 协作网络可运行 | Supervisor 与参与的 Agent／人、授权关系；新增 Agent 如有，具备场景样例验证记录 |
| 真实工作项可推进 | 一项实际工作项的动态任务、执行者、交付物与业务状态变化记录 |
| AI 节拍判断可追溯 | Supervisor 至少生成一条节拍决策记录，含制约分支、汇合／验收影响、风险、可选动作、选择及授权依据、后续结果；有依据的不干预也可 |
| 业务结果可验收 | 阶段门与最终验收的证据、自动放行或有权人确认记录 |
| 失败可回修 | 若试点未通过，保留诊断、修订版本、负责人确认与重验记录 |

这一试点验证场景构建与 Supervisor 运行链可以在真实工作项上工作；单项试点不证明周期缩短或预测准确性长期改善。具体场景、工作项与通过阈值待选定。

场景构建以**可验收的业务结果与完成事件**为入口；Agent 再梳理价值流工作项、参与者、知识、数据、能力和授权，最后用真实工作项完成验证（S-047）。

场景价值流蓝图固定业务里程碑、验收门与授权规则；真实工作项进入时，Agent 依据具体情况动态拆解执行任务、安排协作（S-052）。蓝图和工作项运行计划应分别留存版本；具体变更门禁待定义。

验收门在证据明确且可核验、并由有效预授权覆盖时，可由 Agent 直接放行；需要人的判断、证据不足或超出授权时，交有权的人决策（S-053）。具体证据标准与权限粒度待定义。

最终业务结果的验收若涉及定性目标，必须由人确认（S-055）；Agent 可准备证据并核验其中的定量指标。纯定量结果在证据可核验且有效预授权覆盖时可由 Agent 自动验收，否则交有权的人（S-056）。

证据暂时不足时，Agent 先在授权范围内从连接系统取证或协调其他 Agent 补证，再按交付承诺剩余时间和失约风险及时升级；明确需要人的专业判断时直接提交有权的人（S-054）。补证范围和升级阈值待定义。

平台 Agent 根据价值流提出 Agent 分工与协作关系初稿；价值流负责人修正并确认各 Agent 的权限。新增 Agent 通过场景内样例任务后，网络才承载试点工作项（S-048、S-050）。

## 当前阶段的构建闭环

| 步骤 | 平台与人的协作 | 可检查的产物 |
|---|---|---|
| 定义结果 | 价值流负责人确认业务结果、完成事件和验收者 | 场景目标与验收条件（S-012、S-013、S-047） |
| 梳理价值流 | Agent 引导识别工作项、参与者与候选瓶颈 | 价值流草案及依据（S-027、S-047） |
| 组建网络 | Agent 提出分工、协作关系和知识／数据／能力需求 | Agent 网络与授权草案（S-036、S-039、S-048） |
| 确权 | 价值流负责人修正网络并授予 Agent 权限 | 待能力验证的确认版本（S-034、S-048） |
| 验证新 Agent | 对新增 Agent 运行场景内样例任务，检查能力、数据使用和权限 | 可启用记录（S-049、S-050） |
| 试点验证 | Agent 引导选取含并行成果与汇合门的真实工作项，网络按授权执行，人完成必要决策与验收 | 执行、分支风险判断及协调选择、交付和验收证据（S-045、S-046、S-074） |
| 失败回修 | 未通过验收时，Agent 依据证据诊断并提出修订；负责人确认新版本后重验 | 诊断依据、修订记录和重验结果（S-051） |

网络草案发现现有 Agent 无法覆盖所需能力时，平台 Agent 生成新 Agent 候选，列明其知识、数据、能力和权限，由价值流负责人确认（S-049）。候选再用场景内样例任务验证目标环节能力、数据使用和授权边界，通过后才能进入真实工作项（S-050）。试点未通过验收时，Agent 诊断模型、能力、数据或授权问题，负责人确认修订后重验（S-051）；诊断与通过标准待定义。

## 已明确的理念

1. **以场景组织协作。** 一个场景连接业务目标、价值流、Agent 与人的协作网络、任务执行、权限和评价结果（S-033、S-057）；三者之间的映射关系待讨论。
2. **Agent 主导执行，人承担治理。** Agent 在被授予的范围内执行、协同与调节；人为 Agent 确权，承担责任、设计策略，作出关键决策或批准（S-034）。人仍可参与具体工作（S-019），具体职责边界待定义。
3. **运行节拍服务业务结果。** Agent 网络识别和处置价值流中的瓶颈与交付、质量、成本、合规风险；节拍体现为持续观察、动态协调和效果反馈（S-025～S-032）。
4. **Lab 推动实验进化。** 从协作网络中圈定 Agent 组，让其产出涌现方案；在沙盒内与参照组执行比对，用场景业务效果判断改进方向（S-035）。
5. **决策由知识、数据、能力支撑。** 从当前场景建立共用语义，统一业务概念和关系；Agent 结合知识、数据、能力、策略与授权作出执行决策（S-036、S-037、S-042）。语义网络可迭代，不承担每一步执行决策。三类要素的共享边界见 [Q-20261015-002](issues/Q-20261015-002.md)。
6. **共享与专长分层。** 组织语义网络提供共同含义；经确认的知识、权威场景数据和可发现能力目录在授权约束下跨 Agent 使用。每个 Agent 保留自己的专业经验、任务工作状态，以及已获授权的能力组合（S-039）。共享与使用权限分别管理。
7. **共享知识有晋升门禁。** Agent 在运行或 Lab 中形成的新经验，需要效果证据和价值流负责人确认，才进入场景共享知识（S-040）；跨场景知识如何复用待定义。
8. **场景实验由负责人推广。** Lab 中改善了当前场景业务效果的 Agent 组合或策略方案，经价值流负责人批准后进入正式网络（S-043）。

## 两条闭环（产品化归纳，待确认）

- **运行闭环：** 工作项或外部通知进入 → Agent 确认来源与场景上下文，结合语义、知识、数据、能力和策略判断 → 按所在承载点的协调模式推进任务 → 识别瓶颈与风险 → 在授权内处置或交人决策 → 留存证据并验证业务结果（基于 S-036、S-042、S-057～S-070）。
- **进化闭环：** 选定场景问题与 Agent 组 → 形成候选方案 → 沙盒与参照组比对 → 评价业务效果 → 决定是否调整生产网络或策略。

当前阶段通过真实工作项证明场景构建可运行；Lab 场景内成果进入正式网络的批准边界已明确，其本阶段交付、实验评价指标、对照可比性、灰度与回滚仍待讨论。

知识、数据与能力在本场景内采用分层共享原则；局部经验进入场景共享层须经验证与负责人确认。组织级语义变更的既有原则（S-041）保留为后续阶段讨论，本阶段需管理当前场景的语义版本与细权限；Lab 实验版本随其交付阶段再定义。
