# 原始问题

用户将 XPS 重新定位为“企业级别的 Edge AI PaaS 平台，帮助企业构建私有化的 AI 原生解决方案”（S-078），确认 Edge 同时包含企业本地和现场边缘并可云边协同（S-079）；此前讨论的场景价值流与 Agent 协作网络主要是 PaaS 的内置构建能力（S-080）。

# 问题定义

- 期望状态：顶层定位、部署边界、平台共性能力、内置构建能力和具体解决方案各有清楚的层级及验证方式。
- 当前状态：已有较完整的场景价值流、Agent 协作、节拍、Lab 与真实工作项验证模型（Q-20261015-001），但此前将它们直接作为平台主体，尚未定义 Edge AI PaaS 的通用边界。
- 核心差距：旧首阶段能力清单可以验证场景构建链，却不足以说明企业怎样在本地、现场边缘和云之间构建并交付私有化 AI 原生方案。
- 本轮边界：先对齐产品理念和层级，不从 PaaS 名称直接推断技术选型或完整功能清单。
- 成功判据：能解释 XPS 是什么、价值流／协作网络位于何处、私有化部署与云边协同各承担什么职责，以及第一个方案如何验证平台的可复用性；后两项尚待讨论。

# 结构—运行—机制

## 结构

- 已确认：XPS 顶层是企业级 Edge AI PaaS；部署边界包括企业本地、现场边缘及云边协同；价值流和 Agent 协作网络是内置构建能力（S-078～S-080）。
- 推演：平台共性能力 → 内置方案构建能力 → 场景解决方案，是当前整理层级的候选框架。三层的产品边界与接口尚未确认。
- 待定：私有化的准确边界；企业本地与现场边缘各承载的运行和数据；平台是否提供可替换的开发、运行、治理底座；首发目标企业和方案。

## 运行

- 已有场景链：定义业务结果 → 构建价值流与 Agent 协作网络 → 确权 → 在真实工作项中运行、节拍协调、验收和回修（S-044～S-077）。
- 待讨论的 PaaS 链：企业如何接入自身知识、数据和能力，在哪里配置与部署 Agent，现场与企业本地如何协同，如何观察、升级和演进方案。此处是问题清单，不代表功能承诺。

## 机制

- 产品机制假设：将已讨论的场景构建能力放入 PaaS，可使不同企业基于各自业务目标构建私有化方案；要证明这一点，需区分共性平台配置与一次性定制。
- 技术机制假设：企业本地与现场边缘的职责分配，以及云边协同在网络中断、数据权限和版本变更时的行为，会决定“Edge”是否有可验证的产品含义。具体要求未获确认。
- 验证待定：原有一个真实工作项试点能验证场景执行，但能否验证多部署位置和方案可复用性，需要新增判据。

# Discussion

## Round 1 — 2026-10-21

- 观点：用户确认新定位及 Edge 的企业本地／现场边缘／云边协同范围，并确认价值流与 Agent 网络主要为 PaaS 内置构建能力。
- 证据：S-078～S-080。
- 暂定结论：用 Edge AI PaaS 作为 XPS 顶层叙事，保留此前场景模型作为内置构建能力；不把旧功能清单等同于完整平台范围。
- 未解项：“私有化”的数据、模型、执行和治理边界；企业本地、现场边缘、云的具体分工；首发目标客户与方案；首阶段应验证哪些通用能力。

## Round 2 — 2026-10-21

- 观点：用户选择现场边缘节点与企业中心失联时采用“有限自治”（S-081）。
- 暂定解释：现场边缘可继续已预授权、适合本地处理的采集、判断或固定动作；超出本地授权或需要复杂协作的事项暂停并保留上下文，待企业中心可达后处理。这是基于对话选项的产品化解释，具体动作范围尚未确认。
- 结构影响：方案需明确边缘本地可用的运行能力、授权策略和待同步记录；企业中心承担需要集中协调与决策的能力，具体分工待定义。
- 运行影响：失联检测 → 检查本地授权和所需能力 → 执行允许的动作或挂起 → 记录证据 → 恢复连接后同步与核对；冲突处置和重复执行规则待定义。
- 验证问题：首个试点应检验断连下至少一种允许动作和一种被阻止／挂起动作，以及恢复后的记录一致性；是否纳入首阶段验收待确认。

## Round 3 — 2026-10-21

- 观点：用户确认边缘 Agent 断连期间可按预授权新建工作项，并调度现场的人或设备（S-082）。
- 产品含义：有限自治包含产生新工作项和触发现场执行，不限于采集或缓存事件；具体动作仍须由场景预授权限定。
- 运行含义：边缘本地受理事件、建立工作项、检查调度权限、执行或分派、记录动作与结果，重连后与企业中心同步；工作项身份、重复建项、中心侧状态冲突和设备动作结果核验待定义。
- 风险边界：用户尚未确认哪些设备动作可离线执行、授权期限与撤销如何传播，以及需要现场人员确认的条件。
