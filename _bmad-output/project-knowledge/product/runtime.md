# 产品运行

- 当前阶段流程聚焦按场景价值流独立构建，并用真实工作项跑通最小 Agent 网络运行／验收链（S-044、S-045）；完整节拍优化、场景内 Lab 比对与推广交付时点待确认。
- 已确认的本阶段验证链：构建场景价值流和 Agent 网络 → 选取真实工作项 → 按授权实际推进 → 到达该价值流定义的完成事件 → 指定验收者检查结果与证据（S-013、S-045）；具体试点待选。
- 已确认的试点引导：Agent 向价值流负责人展示候选真实工作项及执行、必要人工决策、验收覆盖情况 → 负责人选择试点 → 平台在运行后检查对应证据（S-046）。
- 已确认的场景构建引导：定义可验收业务结果与完成事件 → Agent 梳理工作项和参与者 → 配置知识、数据、能力、策略与授权 → 真实工作项试运行和验收（S-047）。
- 已确认的网络生成：平台 Agent 从价值流提出分工与协作关系草案 → 价值流负责人修正并确认各 Agent 权限 → 已确权版本承载试点工作项（S-048）。
- 已确认的缺口补齐：现有 Agent 无法覆盖某环节 → 平台 Agent 生成包含知识／数据／能力／权限的新 Agent 候选 → 价值流负责人确认（S-049）→ 按 S-050 验证后启用。
- 已确认的启用链：负责人确权的新 Agent 候选 → 场景内样例任务检验能力、数据使用与权限边界 → 通过后加入可执行网络 → 承载真实工作项（S-050）；失败回修待定义。
- 已确认的试点失败链：真实工作项验收未通过 → Agent 据证据分类模型／能力／数据／授权问题 → 生成修订草案 → 价值流负责人确认 → 新版本重验（S-051）。
- 已确认的逐项规划：真实工作项进入场景蓝图后，Agent 按其具体情况拆解执行任务并安排协作，遵循蓝图中的里程碑、验收门和授权规则（S-052）。
- 产品化归纳：工作项沿业务价值流推进，Agent 与人组成的网络保障价值交付，具体任务由人或 Agent 承担并执行（基于 S-057）；三维事件如何关联待定义。
- 产品化归纳：价值流运行可表现为工作项所关联的业务成果与状态变化（基于 S-059）；状态转移条件和返工路径待定义。
- 已确认的状态投影：工作项等待、阻塞或出现失约风险时，将运行状态投影到所在业务价值承载点，以观察停滞和瓶颈（S-060）。
- 已确认的双模式运行：场景协调可由 Supervisor Agent 主导，也可由多个 Agent 群体协调（S-061）；群体决议及模式切换路径待定义。
- 产品化归纳：工作项进入某价值承载点时采用该点覆盖模式，否则采用场景默认模式（基于 S-062）；跨模式交接及运行中修改待定义。
- 已确认的群体协调流程：有权限 Agent 根据瓶颈或风险提出动作 → 受影响 Agent／人反馈能力、责任和风险 → 规则内无冲突则执行；冲突则 Agent 协商，决策管理员确认后生效（S-063）。
- 已确认的 Supervisor 流程：参与 Agent 报告瓶颈、风险和建议 → Supervisor 汇总并在预授权内选择／下达调度动作 → 受影响方反馈冲突 → 冲突方案交决策管理员确认（S-064）。
- 已确认的并行运行：一个工作项可同时推进多个业务成果／状态（S-065）。产品化归纳：各路径应能分别关联执行与验收证据；汇合事件待定义。
- 已确认的汇合运行：并行成果按蓝图中的必备／择一／豁免条件检查后进入下一业务状态；Agent 可调度分支任务，临时改变汇合条件先交负责人确认（S-066）。
- 已确认的构建交互：平台 Agent 对话引导 → 生成价值流与协作网络图 → 负责人直接修订 → 用真实工作项展示任务、风险、证据（S-067）；编辑同步待定义。
- 初步认可的协作运行类型：交接成果、共同执行、请求授权／决策、替补接手／升级（S-068）；信息反馈路径待定义。
- 已确认的信息运行：Agent 可接收外部通知，协作网络按观察／反馈关系传递状态和风险信号（S-069）；关联与动作边界见 S-070，异常处理待定义。
- 已确认的通知运行：外部消息定向投递或按场景事件订阅 → Agent 确认来源并关联工作项 → 按已有授权决定是否行动（S-070）。
- 已确认的新项受理：通知无既有工作项关联 → Agent 核对来源、场景和预设受理规则 → 满足则创建新工作项，否则交负责人判断并保留原通知（S-071）。
- 已确认的建项后运行：Agent 自动建项后可在授权内准备／执行并预测完成时间；负责人确认预测后才产生对客户的交付承诺（S-072）。
- 已确认的节拍协调：Agent 识别制约汇合门／最终验收的并行分支，结合承诺剩余时间与交付、质量、成本、合规风险优先协调（S-073）；动作效果跟踪待定义。
- 已确认的首个试点运行：真实工作项经过并行成果及汇合门，Agent 至少产生一次可追溯的分支风险判断和协调选择（含有依据的暂不干预）（S-074）。
- 已确认的首个试点模式运行：只要求一种协调模式完成真实工作项的协调链（S-075）；另一模式与跨模式交接另定验证时点。
- 已确认的首个试点采用 Supervisor 模式（S-076），按 S-064 的汇总、授权内选择和下达链运行。
- 已确认的决策留痕：Supervisor 协调时创建工作项节拍决策记录，保存判断快照、选择依据和后续结果；暂不干预也记录理由（S-077）。
- 已确认的协作网络运行边界：负责人确认的场景网络可复用；逐项运行中动态选择参与者、拆解与转派任务；长期网络变更由负责人确认新版本（S-058）。
- 已确认的验收门运行：证据明确可核验且有效预授权覆盖时 Agent 放行；需人判断、证据不足或超授权时提交有权人决策（S-053）。
- 已确认的补证运行：证据暂缺 → Agent 在授权内从连接系统或协作 Agent 补证 → 按承诺剩余时间和失约风险及时升级；需要人的专业判断直接交人（S-054）。
- 已确认的最终验收运行：业务结果涉及定性目标时提交人类验收者确认（S-055）；纯定量目标在证据可核验且预授权有效时 Agent 自动验收，否则交有权的人（S-056）。
- 已确认的整体方向：围绕场景构建 Agent 协作网络，Agent 承担核心执行，人负责确权、策略设计和关键决策／批准（S-033、S-034）；具体网络组建和运行链待定义。
- 已确认的 Lab 方向：圈定 Agent 组 → 产出涌现方案 → 在沙盒内与参照组执行比对 → 评价场景业务效果（S-035）；实验成果如何进入生产待定义。
- 已确认的决策方向：Agent 在场景中由知识、数据、能力驱动生产与决策，组织语义网络可迭代（S-036、S-037）；要素获取、共享和更新路径待定义（S-038）。
- 已确认的分层使用：Agent 按权限引用共享知识与场景数据、发现可用能力，并以自身配置和任务状态执行；目录可见、资源访问与能力调用分别受控（S-039）。具体权限检查待定义。
- 已确认的知识晋升链：Agent 局部经验 → 运行或 Lab 效果验证 → 价值流负责人确认 → 场景共享知识（S-040）；候选证据与状态转换细节待定义。
- 后续阶段语义变更链：Agent／价值流负责人提出跨场景变更 → 企业指定语义责任人确认 → 更新组织语义网络（S-041、S-044）；当前场景语义迭代细节待定义。
- 已确认的执行决策：Agent 以统一语义理解场景对象，再结合知识、数据、能力、策略与授权决定具体动作（S-042）；不由语义变更直接驱动逐步执行。
- 已确认的场景内 Lab 理念链：候选方案 → 本场景沙盒参照组比对 → 形成效果证据 → 价值流负责人批准 → 生效为本场景正式 Agent 网络／策略版本（S-043、S-044）；交付时点、灰度与回滚待定义。

- 待确认：需求进入、任务分派、执行、交接、异常升级、复盘的完整产品行为。
- 已确认的局部流程：平台显露冲突 → Agent 推进协商并形成方案 → 决策管理员确认 → 方案生效；无冲突且在授权规则内的日常调节可自动执行（S-007～S-010）。
- 已确认：工作项在 Agent 平台中管理，Agent 可通过连接能力驱动其他平台（S-011）。
- 已确认：顶层工作项按照所属价值流配置的完成事件，由指定验收者验收（S-013）；具体验收交互待定义。
- 已确认：Agent 生成节拍建议 → 价值流负责人确认目标与自动调节范围 → Agent 在授权范围内观察并调节（S-014）。
- 已确认：平台需观察顶层工作项从客户需求进入到所属价值流验收的历程，并呈现交付时间预测与实际结果（S-013、S-015）；事件细节待定义。
- 已确认：Agent 生成完成时间预测 → 价值流负责人确认 → 形成对客户的交付承诺（S-016）。
- 已确认：后续预测出现失约可能性时立即向价值流负责人呈现风险；授权内的恢复动作可依既定自动调节规则执行，具体动作待定义（S-010、S-017）。
- 已确认：平台不直接向客户发送风险信息；负责人决定对外沟通（S-018）。
- 用户提出的瓶颈处理流程：识别瓶颈 → 按策略启动 Agent 代办准备／执行或转派其他 Agent／人 → 由有权的人决定是否通过（S-019）；触发和审批细节待定义。
- 已确认的负责人未响应路径：请求代理人接受 → 代理人未接手时升级给决策管理员（S-020）；接受、超时和最终决定的状态规则待定义。
- 已确认：代理人接手后，平台校验其授权；授权有效且覆盖该事项时，代理人可直接决定通过（S-021）。
- 已确认：价值流负责人预先授权代理人；发生未响应后平台先请求代理人接手，再依据预授权核验其通过权（S-022）。
- 已确认：代理人仍未响应 → 平台升级给决策管理员 → 管理员直接决定通过或不通过（S-023）；升级判定和时限待定义。
- 已确认：Agent 持续比较交付承诺剩余时间与失约风险，在等待可能侵蚀承诺缓冲时提前触发代理人及管理员升级（S-024）；具体阈值待定义。
- 用户强调的 AI 节拍核心闭环（产品归纳）：持续感知 → 预测失约风险 → 在授权内选择代办、转派或升级 → 观察响应和交付结果（S-019、S-024、S-025）；策略细节待定义。
- 用户进一步界定的核心闭环（产品归纳）：识别价值流瓶颈 → 评估交付风险 → 选择并执行授权内处置 → 观察瓶颈是否缓解（S-026）；未响应升级为其中一个场景。
- 待确认的双阶段识别假设：价值流构建时标记候选瓶颈，运行中依据工作项事件验证或修正，再据处置结果复核瓶颈是否缓解或转移（Round 27）。
- 已确认构建期一侧：Agent 汇集历史数据和团队经验提出候选瓶颈 → 价值流负责人确认（S-027）；运行期如何改变瓶颈状态待定义。
- 已确认运行期一侧：发现新瓶颈 → 立即呈现证据与交付风险 → 按现有授权处置 → 观察结果；若要固化模型或改变长期策略，提交价值流负责人确认（S-028）。
- 已确认的动作选择链：读取企业级约束与本流策略 → 依据瓶颈及风险筛选可行动作 → Agent 在授权内选取并执行 → 记录结果（S-029）；具体选择与回退逻辑待定义。
- 已确认的流入调节：检测环节积压 → 在负责人预设范围内暂缓上游新工作进入该环节 → 持续观察瓶颈及承诺风险 → 缓解后恢复流入（S-030）；工作项仍保留并可追踪。
- 已确认的选择性放行：暂缓期间评估已承诺工作项的失约风险，符合预设例外规则时允许进入；记录放行理由及对瓶颈队列和其他承诺的影响（S-031）。
- 已确认：处置前后 Agent 需观察交付失约、质量、成本和合规风险的变化（S-032）；跨风险权衡规则待定义。
- 待确认：价值流建模、工作项进入、任务分派、状态感知、执行、交接和效果评估的完整行为。
