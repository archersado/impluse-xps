# 产品机制

- 阶段边界：`structure.md` 中每条场景价值流及其 Agent 网络作为独立单元，支撑 `runtime.md` 中本阶段的构建与一个真实工作项的最小验证（S-044、S-045）；完整节拍优化与 Lab 交付时点待确认，跨场景机制后置。
- 已确认的最小验证机制：`structure.md` 中真实工作项、Agent 网络、授权关系和验收者支撑 `runtime.md` 中从进入到完成事件的实际执行（S-013、S-045）；以交付物与验收记录验证配置可运行，周期改善与可预测性仍需后续样本。
- 已确认的试点选择机制：`structure.md` 中候选工作项与执行／决策／验收节点覆盖信息，支撑 `runtime.md` 中 Agent 引导负责人选定试点并核对证据（S-046）；代表性算法和失败复盘待定义。
- 已确认的构建顺序机制：`structure.md` 中业务结果及完成事件作为价值流和 Agent 网络的目标锚点，`runtime.md` 中 Agent 据此梳理工作项、角色、知识／数据／能力和授权并运行试点（S-047）；通过验收证据验证配置。
- 已确认的网络生成门禁：`structure.md` 中 Agent 网络草案与已确权版本分离，`runtime.md` 中负责人修正并授予权限后才能驱动真实工作项（S-048）。推导依据及变更追溯待定义。
- 已确认的能力缺口机制：`structure.md` 中新 Agent 候选绑定所需知识、数据、能力与授权，`runtime.md` 中平台 Agent 在现有 Agent 不足时生成候选并交负责人确认（S-049）。从候选到可执行须经过 S-050 的样例验证。
- 已确认的新 Agent 启用机制：`structure.md` 中候选 Agent 与样例任务／授权检查结果关联，`runtime.md` 中验证通过后才允许其承担真实工作项（S-050）。需区分能力可用性验证与 Lab 的业务效果对照。
- 已确认的失败回修机制：`structure.md` 中试点证据、修订草案及负责人确认的新版本，支撑 `runtime.md` 中失败归因和重验（S-051）。以验收结果检查修订是否有效，诊断准确性与终止规则待定义。
- 已确认的稳定边界与动态执行：`structure.md` 中场景蓝图的里程碑、验收门和授权规则约束工作项运行计划，`runtime.md` 中 Agent 为每个工作项动态拆解与协调（S-052）；以是否遵守验收与授权边界、是否留有执行证据检验，计划变更门禁待定义。
- 产品化归纳的三维协同机制：`structure.md` 中业务价值流、Agent／人协作网络与任务执行三种结构，支撑 `runtime.md` 中价值推进、主体协作及任务分派执行（基于 S-057）；拟以任务交付物能否追溯至价值承载点和验收结果检查关联，具体映射待定义。
- 产品化归纳的价值状态机制：`structure.md` 中业务成果／状态承载点，支撑 `runtime.md` 中工作项的价值状态变化（基于 S-059）；以产物与验收证据验证变化，状态转移规则待定义。
- 已确认的状态投影机制：`structure.md` 中分离的业务价值状态与工作项运行状态，支撑 `runtime.md` 中等待／阻塞／风险投影到价值流（S-060）；以停滞位置与时长检查瓶颈识别，阈值待定义。
- 已确认的双协调模式：`structure.md` 中 Supervisor 与群体协调两种场景网络配置，支撑 `runtime.md` 中分别由协调 Agent 主导或多个 Agent 分担节拍动作（S-061）；两种模式均需检验动作授权与结果追溯，责任及切换规则待定义。
- 产品化归纳的模式继承：`structure.md` 中场景默认模式及承载点覆盖值，支撑 `runtime.md` 中工作项按所在承载点选择协调方式（基于 S-062）；应以交接记录检查跨模式连续性，具体切换规则待定义。
- 已确认的群体协调门禁：`structure.md` 中提案权、受影响方、规则及管理员确认关系，支撑 `runtime.md` 中提案、反馈、无冲突执行或冲突协商确认（S-063）；以动作依据、反馈和确认记录检查授权与责任。
- 已确认的 Supervisor 调度门禁：`structure.md` 中 Supervisor 预授权与受影响方／管理员关系，支撑 `runtime.md` 中建议汇总、授权内调度及冲突确认（S-064）；以汇总依据、权限检查和下达记录检验动作。
- 产品化归纳的并行推进机制：`structure.md` 中工作项与多个价值承载点的关联，支撑 `runtime.md` 中并行形成成果／状态（基于 S-065）；拟分别留证并以汇合条件检查整体推进，汇合规则待定义。
- 已确认的汇合门禁：`structure.md` 中蓝图的必备、条件择一／豁免规则和负责人确认权，约束 `runtime.md` 中并行成果汇合及临时条件变更（S-066）；以汇合证据、豁免依据和确认记录核验。
- 已确认的双图构建机制：`structure.md` 中 Agent 对话和两张可编辑图，支撑 `runtime.md` 中引导生成与负责人修订（S-067）；应以图与执行蓝图的一致性检查确认结果，具体同步机制待定义。
- 初步认可的协作关系机制：`structure.md` 中交接、共同协作、授权／决策、替补／升级关系，支撑 `runtime.md` 中相应的成果流转与协同行为（S-068）；以实际交接、决策与接手记录检查关系可运行，信息流另见 S-069。
- 已确认的信息可达机制：`structure.md` 中观察／反馈关系与 Agent 外部消息入口，支撑 `runtime.md` 中状态／风险通知到达相关 Agent（S-069）；以通知接收、关联和后续处置记录检查可达性，可信度与授权检查待定义。
- 已确认的通知授权边界：`structure.md` 中定向／订阅关系、来源与既有授权，约束 `runtime.md` 中 Agent 接收、关联并决定动作（S-070）；通知不扩展行动权限，以来源、工作项及动作授权记录检查。
- 已确认的新项受理门禁：`structure.md` 中可信来源、场景归属、受理规则与负责人，约束 `runtime.md` 中 Agent 创建新工作项或提交判断（S-071）；以通知原文、匹配依据与创建／拒绝记录核验。
- 已确认的建项／承诺分离：`structure.md` 中工作项、执行授权、Agent 预测及负责人确认后的承诺分别承载，支撑 `runtime.md` 中建项后授权内执行与后续承诺确认（S-072）；以执行权限和确认记录检查边界。
- 已确认的汇合风险节拍：`structure.md` 中分支、汇合门、承诺与多类风险，支撑 `runtime.md` 中 Agent 识别制约最终验收的分支并优先协调（S-073）；以汇合时间和风险变化检验动作效果，计算方法待定义。
- 已确认的试点节拍验证：`structure.md` 中并行汇合和判断／选择证据，支撑 `runtime.md` 中真实工作项至少一次节拍判断（S-074）；检查判断依据、所选动作及实际结果，单项试点不推断长期绩效改善。
- 已确认的试点模式门槛：`structure.md` 中首选一种协调模式的网络配置，支撑 `runtime.md` 中该模式跑通真实项（S-075）；以协调动作及验收记录检查，双模式交接不计入首个试点必需项。
- 已确认的 Supervisor 试点：`structure.md` 中明确 Supervisor Agent 及其预授权，支撑 `runtime.md` 中首个真实工作项的风险汇总和协调选择（S-076）；以判断依据、下达动作与反馈记录核验。
- 已确认的节拍可复核机制：`structure.md` 中工作项关联的决策记录及预测／风险／动作／授权／结果字段，支撑 `runtime.md` 中 Supervisor 的协调与结果回看（S-077）；以记录完整性及实际结果检查判断，回看规则待定义。
- 已确认的双层变更机制：`structure.md` 中经负责人确认的场景协作网络版本与逐项计划／转派记录，支撑 `runtime.md` 中网络复用、动态调度及长期修订（S-058）；以每项任务能追溯所用网络版本和授权检查边界，具体生效规则待定义。
- 已确认的验收门放行机制：`structure.md` 中门的证据要求、预授权和有权决策人，约束 `runtime.md` 中 Agent 自动放行或提交人的判断（S-053）；用证据、授权与决策记录核验每次放行，充分性标准待定义。
- 已确认的补证与升级机制：`structure.md` 中待补证门、取证路径、承诺及风险，支撑 `runtime.md` 中 Agent 在授权内补证并按失约风险升级（S-054）；以补证记录、等待时间及升级时点检查是否避免无谓停滞，阈值待定义。
- 已确认的定性验收门禁：`structure.md` 中定性业务目标及其人类验收者，约束 `runtime.md` 中最终业务结果交人确认（S-055）；以验收意见与确认记录核验，混合目标处理待定义。
- 已确认的纯定量验收门禁：`structure.md` 中量化目标、可核验证据及 Agent 预授权，约束 `runtime.md` 中纯定量业务结果自动验收或交人（S-056）；以指标口径、证据和授权记录检查判定。
- 已确认的场景协作机制：`structure.md` 中场景、Agent 网络与人的治理角色，支撑 `runtime.md` 中 Agent 核心执行及人类确权、策略和审批节点（S-033、S-034）；责任与权限的具体映射待定义。
- 已确认的 Lab 方向：`structure.md` 中 Agent 组、方案、沙盒、参照组与业务效果，支撑 `runtime.md` 中生成、执行比对和评价（S-035）；何种结果可推广及由谁批准待定义。
- 已确认的决策要素方向：`structure.md` 中知识、数据、能力与统一语义网络，支撑 `runtime.md` 中 Agent 的生产、决策和跨 Agent 协作（S-036、S-037）；资源共享原则见 S-039。
- 已确认的分层共享机制：`structure.md` 中共同语义、共享资源与 Agent 自身配置分层，`runtime.md` 中 Agent 依据独立的访问及调用权限使用资源（S-039），以支持跨 Agent 协作且保留专长与任务上下文；资源更新与权限审计待定义。
- 已确认的知识晋升机制：`structure.md` 中局部、候选与场景共享知识状态由负责人确认关系连接；`runtime.md` 中效果验证和确认后才发布供其他 Agent 使用（S-040）。验证质量与撤回待定义。
- 后续阶段语义变更门禁：`structure.md` 中语义责任人与跨场景提案绑定，`runtime.md` 中确认后才更新组织共用网络（S-041、S-044）；当前阶段只使用场景所需语义。
- 已确认的语义与决策分工：`structure.md` 中语义网络定义共同概念／关系，知识、数据、能力、策略与授权定义 Agent 可用的决策要素；`runtime.md` 中 Agent 结合它们作出动作选择（S-042）。语义版本和决策依据留痕待定义。
- 已确认的场景内 Lab 理念门禁：`structure.md` 中实验候选与正式场景版本分离并关联价值流负责人；`runtime.md` 中方案带对照证据经其批准后才在本场景生效（S-043、S-044）。本阶段交付时点、业务效果和回退标准待定义。

- 已确认的权限机制：`structure.md` 中的价值流负责人及协商规则限定 Agent 的行动范围；`runtime.md` 中无冲突调节在授权内自动执行，冲突协商方案通过决策管理员确认后才生效（S-005、S-008～S-010）。
- 已确认的主系统边界：`structure.md` 中的工作项由 Agent 平台承载；`runtime.md` 中 Agent 以工作项为入口驱动连接的外部平台（S-011）。外部执行事实如何回传和核验尚待定义。
- 已确认的交付单位：`structure.md` 中的顶层工作项代表可验收的业务结果；其在 `runtime.md` 中如何分解、推进和验收尚待定义（S-012）。
- 已确认的完成机制：`structure.md` 中每条价值流配置完成事件和验收者，`runtime.md` 中顶层工作项据此进入验收；具体证据、确认及撤销规则待定义（S-013）。
- 已确认的节拍机制：`structure.md` 中的价值流负责人设置目标和授权范围，`runtime.md` 中 Agent 提议后观察需求、产能和实际交付并在范围内调节；工作类型、规模、指标与异常处理待定义（S-014）。
- 已确认的成效检验：以 `structure.md` 中顶层工作项的可验收业务结果为单位，利用 `runtime.md` 中需求进入、预测、验收事件检验周期与可预测性；具体指标和防止隐藏等待的规则待定义（S-012、S-013、S-015）。
- 已确认的预测与承诺边界：`structure.md` 中区分 Agent 预测和对客户交付承诺；`runtime.md` 中预测经价值流负责人确认才变成承诺（S-016）。承诺变更和历史追溯机制待定义。
- 已确认的风险显露：`runtime.md` 中 Agent 预测可能失约时立即呈现风险，供 `structure.md` 中的价值流负责人判断承诺与调节；风险阈值和呈现范围待定义（S-017）。
- 已确认的沟通门禁：`structure.md` 中的价值流负责人控制对客户风险沟通，`runtime.md` 中平台只在内部呈现风险，不直接向客户传达（S-018）。
- 待验证的瓶颈机制：`structure.md` 中需定义瓶颈策略及可替代执行者，`runtime.md` 中按策略把准备／执行工作交给 Agent 或其他人；最终通过保留给有权的人（S-019）。策略触发条件和代理决策权限 pending。
- 已确认的顺序门禁：`structure.md` 中的代理人先收到负责人未响应事项，`runtime.md` 中代理人未接手才升级给决策管理员（S-020）；代理授权范围、超时阈值和管理员处理权限待定义。
- 已确认的代理审批门禁：`structure.md` 中代理人的授权覆盖范围决定其通过权；`runtime.md` 中只有授权有效且覆盖当前事项，代理人的“通过”才生效（S-021）。授权记录、期限和撤销规则待定义。
- 已确认的授权来源：`structure.md` 中价值流负责人预先配置代理授权；`runtime.md` 中负责人未响应后按该授权请求代理人接手并核验决定（S-022）。
- 已确认的升级决策门禁：`structure.md` 中决策管理员持有升级审批权，`runtime.md` 中代理人仍未响应时由其决定通过或不通过（S-023）。具体触发条件和留痕待定义。
- 已确认的动态升级机制：`structure.md` 中已确认交付承诺及决策链为输入，`runtime.md` 中 Agent 按承诺剩余时间与失约风险提前推进到下一有权角色（S-024）。风险信号、阈值和无承诺事项的替代依据待定义。
- 核心节拍机制（产品归纳）：`structure.md` 中的承诺、瓶颈策略和授权链支撑 `runtime.md` 中持续感知、预测、协调和反馈闭环（S-019、S-024、S-025）；用等待时间、需求到验收周期和预测偏差检验效果，指标口径待定义。
- 核心机制的用户界定：`structure.md` 中的瓶颈、风险、策略和授权关系支撑 `runtime.md` 中识别、评估、处置和反馈（S-026）；动态升级只是一类处置动作，对客户沟通仍由负责人把控（S-018）。
- 待验证的识别机制：`structure.md` 中的价值流模型可承载候选瓶颈；`runtime.md` 中的等待、排队、返工和交付事件用于验证实际瓶颈，并在处置后重新评估（Round 27）。此为产品分析，尚待用户确认。
- 已确认的构建期候选机制：`structure.md` 中的候选瓶颈及负责人确认记录，承载 `runtime.md` 中 Agent 依据历史数据与团队经验提出的初始判断（S-027）；对实际瓶颈的验证规则仍待确认。
- 已确认的运行期处置与变更门禁：`structure.md` 中瓶颈发现记录可独立于长期模型版本，价值流负责人控制长期模型与策略；`runtime.md` 中 Agent 即时显露风险并执行现有授权内的动作，长期变更经负责人确认后生效（S-028）。
- 已确认的策略层级机制：`structure.md` 中企业级规则限制价值流处置策略，价值流策略限定 Agent 动作集合；`runtime.md` 中 Agent 按实时瓶颈和风险选择授权内动作（S-029）。需记录规则版本、选择依据和处置效果，具体要求待定。
