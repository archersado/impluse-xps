# 项目概览

- **当前顶层定位（2026-10-21）：** XPS 是企业级 Edge AI PaaS，帮助企业构建私有化 AI 原生解决方案；支持企业本地与现场边缘，并可云边协同（S-078、S-079）。场景价值流和 Agent 协作网络主要是 PaaS 内置构建能力（S-080）。平台共性能力与首阶段范围正在 [Q-20261021-001](issues/Q-20261021-001.md) 中复核。
- 现场边缘断连采用有限自治作为基础原则（S-081）；本地允许动作、中心依赖与恢复同步规则待定义。
- 边缘 Agent 可在断连期间按预授权新建工作项、调度现场人或设备（S-082）；重连去重与设备动作约束待定义。
- 以下 2026-10-10～15 的内容记录定位演化与已讨论的场景能力；凡将“场景价值流平台”作为顶层定位、或将原试点清单视作完整 PaaS 交付范围的表述，均以当前定位更新为准。
- 项目意图（用户陈述，2026-10-10）：以精益生产理论设计企业级 Agent 平台，让团队成员同频协作，由 Agent 协调员工与数字员工的组织生产节奏。
- 用户于 2026-10-15 明确产品核心：围绕业务场景构建 Agent 协作网络；Agent 是核心执行主体，人负责确权、责任、决策／批准和策略设计（S-033、S-034）。理念讨论稿：[product-philosophy.md](product-philosophy.md)。
- 首阶段功能清单与场景工作台交互流程讨论稿：[first-phase-features-and-workbench.md](first-phase-features-and-workbench.md)；首个真实工作项采用 Supervisor 并验证并行汇合及节拍决策（S-074～S-077）。
- 当前阶段以场景价值流为独立单元构建 Agent 网络；场景数量未限定，完整运行节拍与场景内 Lab 保留为理念，交付时点待确认；跨场景事项后置（S-044）。
- 场景构建需要用一个真实工作项跑通并验证（S-045）；因此最小运行链属于本阶段，Lab 对照实验仍待排期。
- 平台 Agent 引导价值流负责人挑选真实试点工作项，覆盖 Agent 执行、必要人工决策与验收证据（S-046）。
- 场景构建顺序为先定义可验收业务结果和完成事件，再梳理工作项、参与者及知识／数据／能力与授权，最后用真实工作项验证（S-047）。
- 平台 Agent 根据价值流生成 Agent 分工与协作关系初稿，价值流负责人修正并确权后供真实工作项使用（S-048）。
- 现有 Agent 能力不足时，平台 Agent 生成列明知识、数据、能力与权限的新 Agent 候选，交价值流负责人确认（S-049）。
- 新 Agent 经负责人确权后须通过场景内样例任务，验证能力、数据使用和授权边界，才可进入真实工作项（S-050）。
- 真实工作项验收失败时，Agent 据证据诊断价值流模型、能力、数据或授权问题，提出修订草案，负责人确认后重验（S-051）。
- Lab 涌现中心：圈定 Agent 组生成方案，在沙盒与参照组执行比对，推动场景业务效果进化（S-035）；具体形态与推广门禁待讨论。
- Agent 的生产与决策需由知识、数据、能力三类要素驱动；组织有统一、可迭代的语义网络（S-036、S-037）。共享问题由 [Q-20261015-002](issues/Q-20261015-002.md) 追踪，细化规则待讨论。
- 用户确认分层共享：共同语义、受控共享知识／数据／能力目录，加上 Agent 自身专业经验、任务状态和获授权的能力组合（S-039）。
- Agent 局部经验经运行或 Lab 效果验证后，须价值流负责人确认才成为场景共享知识（S-040）。
- Agent 与价值流负责人提出跨场景语义变更、企业指定语义责任人确认的原则（S-041）保留为后续阶段治理议题（S-044）。
- 语义网络统一概念和关系；Agent 在场景中综合知识、数据、能力、策略与授权决定执行，不由语义网络逐步驱动（S-042）。
- 理念中的 Lab 仅推广本场景 Agent 组合／策略成果，由价值流负责人批准（S-043、S-044）；其本阶段交付时点待定，跨场景推广规则后置。
- 当前阶段：产品概念探索。平台需要支持企业定义价值流，并由 Agent 引导选择、追问和建模；“客户需求到产品上线”是示例价值流（S-003）。目标客户、首发场景和成功指标尚未确认。
- 节拍器目标覆盖三个行动层级：建议、在规则内分派、在授权范围内自动调节（S-004）；权限与升级规则尚待定义。
- Agent 节奏协调的授权主体为价值流负责人（S-005）。
- 个人任务优先级须结合岗位职责与员工的责任、关注（S-006）；具体排序和冲突规则待定义。
- 岗位设定基础责任，个人维护专业目标与风险关注；冲突须在平台中显露（S-007）。
- 平台支持由 Agent 推进冲突协商；企业经营者设置协商策略与规则（S-008）。
- 协商结果须由决策管理员角色确认后生效（S-009）。
- 无冲突且在授权规则内的日常调节可自动执行；有冲突的协商结果须经决策管理员确认（S-010）。
- Agent 平台是工作项主系统；其他平台作为可连接、可被 Agent 驱动的系统（S-011）。
- 顶层工作项以可验收的业务结果为单位（S-012）；子项分解与验收证据尚待定义。
- 每条价值流可设定顶层工作项的完成事件并指定验收者（S-013）。
- 节拍目标由 Agent 依据需求、产能和交付数据提议，经价值流负责人确认，再在授权范围内持续调整（S-014）。
- 首要成效：客户需求到验收的周期缩短、交付时间更可预测（S-015）。
- Agent 的完成时间预测经价值流负责人确认后，才能成为对客户的交付承诺（S-016）。
- 预测显示可能失约时，平台立即呈现风险（S-017）。
- 风险先向价值流负责人呈现；Agent 平台不直接向客户传达，由负责人把控对外沟通（S-017、S-018）。
- 用户提出按瓶颈策略处理未响应或积压：Agent 可承担大部分准备或执行工作并交人作最终通过决定，也可重分配给其他 Agent／人（S-019）；权限和触发条件待定义。
- 负责人未响应的升级顺序为先请代理人接受，再升级给决策管理员（S-020）；代理授权与升级时限待定义。
- 代理人获得授权后可以直接决定通过（S-021）；授权主体、范围、期限与撤销规则待定义。
- 代理人的通过权由价值流负责人预先授予（S-022）；范围和有效期仍待定义。
- 代理人仍未响应时升级给决策管理员，其可直接决定通过或不通过（S-023）；升级时限待定义。
- 升级由 Agent 根据交付承诺剩余时间与失约风险提前触发（S-024）；风险阈值和无承诺事项的处理待定义。
- 用户明确：这种动态提前协调是体现 AI 节拍的核心能力（S-025）。
- 用户进一步明确 AI 节拍核心是把握瓶颈和风险的处置能力（S-026）；动态升级只是其中一类动作。
- 构建价值流时，Agent 结合历史数据和团队经验提出候选瓶颈，供价值流负责人确认；运行中仍需验证（S-027）。
- 运行中发现新瓶颈时，Agent 立即呈现证据与交付风险，并在现有授权内处置；固化到长期价值流模型或改变长期策略须价值流负责人确认（S-028）。
- 瓶颈处置策略按三层分工：企业经营者设统一权限和风险规则，价值流负责人配置本流策略，Agent 运行中在授权范围内选动作（S-029）。
- 当环节积压时，Agent 可在负责人预设范围内暂缓上游工作进入，瓶颈缓解后恢复（S-030）；承诺影响与例外规则待定义。
- 暂缓期间，已有交付承诺且高失约风险的工作项可按预设规则例外进入（S-031）；须评估对瓶颈和其他承诺的影响。
- Agent 的风险识别与处置覆盖交付失约、质量、成本和合规（S-032）；跨风险权衡与权限门禁待定义。
