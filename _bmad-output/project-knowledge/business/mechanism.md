# 业务机制

- 阶段边界：`structure.md` 中以每条场景价值流为独立单位，`runtime.md` 中当前聚焦构建及一个真实工作项的最小验证（S-044、S-045）；完整节拍优化与 Lab 交付时点待定，跨场景治理后置。
- 已确认的场景验证：`structure.md` 中独立的场景价值流及其 Agent／人类角色，支撑 `runtime.md` 中一个真实工作项的实际流转与验收（S-045）；用完成事件和验收证据检查可运行性，长期业务成效仍需更多样本。
- 已确认的试点覆盖机制：`structure.md` 中的 Agent 执行角色、人类决策者和验收者，支撑 `runtime.md` 中由 Agent 引导负责人选取的真实工作项（S-046）；按实际需要覆盖这些节点，具体代表性判据待定义。
- 已确认的结果驱动构建：`structure.md` 中场景业务结果、完成事件与责任角色，支撑 `runtime.md` 中 Agent 从验收目标推导工作项与资源，再用真实工作项验证（S-047）。步骤确认和失败回修待定义。
- 已确认的网络确权门禁：`structure.md` 中价值流负责人有网络修正与授权职责，`runtime.md` 中 Agent 草案经其确认后才用于真实工作项（S-048）；需核对权限与责任边界。
- 已确认的能力补齐：`structure.md` 中价值流负责人确认新 Agent 候选的职责与授权，`runtime.md` 中平台 Agent 据能力缺口生成候选定义（S-049）。启用须经过 S-050 的样例验证，具体标准待定义。
- 已确认的新 Agent 启用门禁：`structure.md` 中负责人确权的新 Agent 候选，在 `runtime.md` 中通过场景内样例任务验证能力、数据使用和权限后才进入真实工作项（S-050）；具体通过标准待定义。
- 已确认的回修门禁：`structure.md` 中价值流负责人确认场景与网络修订，`runtime.md` 中 Agent 在真实工作项失败后据证据提出修订并重验（S-051）；须保留前后版本与失败证据。
- 已确认的场景约束机制：`structure.md` 中蓝图的业务里程碑、验收门及授权规则支撑 `runtime.md` 中 Agent 对具体工作项的动态任务安排（S-052）；通过验收与授权记录检查动态安排是否守住场景边界，偏离时的确认路径待定义。
- 产品化归纳的三维价值交付机制：`structure.md` 中价值流的承载点、Agent／人协作关系与可分派任务，支撑 `runtime.md` 中价值推进、协作与执行（基于 S-057）；拟通过任务结果与业务验收之间的追溯检查协作是否产生价值，映射规则待定义。
- 产品化归纳的成果承载机制：`structure.md` 中的业务成果／状态节点，支撑 `runtime.md` 中价值形成和状态推进（基于 S-059）；以成果证据与验收记录检查价值是否形成，状态判据待定义。
- 已确认的停滞可见性机制：`structure.md` 中的业务价值状态与工作项运行状态相互关联，支撑 `runtime.md` 中等待、阻塞和失约风险投影到价值流（S-060）；以等待时长和风险记录验证瓶颈可观察性。
- 已确认的协调模式选择边界：`structure.md` 中的 Supervisor 与群体协调配置，支撑 `runtime.md` 中不同的 Agent 协调方式（S-061）；无论模式如何，授权、冲突确认与业务责任仍须按已确认角色落实，具体机制待定义。
- 产品化归纳的模式配置机制：`structure.md` 中场景默认及承载点覆盖模式，支撑 `runtime.md` 中工作项在不同业务成果／状态间采用相应协调方式（基于 S-062）；以交接责任和证据检查连续性，具体规则待定义。
- 已确认的群体行动形成机制：`structure.md` 中有权限的提案 Agent、受影响方与决策管理员，支撑 `runtime.md` 中提案、反馈、规则内执行及冲突确认（S-063）；以提案和决议记录检验责任与授权，未响应处理待定义。
- 已确认的 Supervisor 行动形成机制：`structure.md` 中 Supervisor 的预授权及受影响方／管理员关系，支撑 `runtime.md` 中建议汇总、调度下达及冲突确认（S-064）；以授权和动作记录检验责任，失联接管待定义。
- 产品化归纳的并行价值形成机制：`structure.md` 中工作项关联的多个业务成果／状态，支撑 `runtime.md` 中同时推进（基于 S-065）；拟通过各路径证据与最终结果检验其贡献，分别验收及汇合门禁待定义。
- 已确认的业务汇合门禁：`structure.md` 中蓝图的必备／择一／豁免条件与负责人确认权，约束 `runtime.md` 中多成果汇合及临时变更（S-066）；以分支成果和豁免记录检查下一状态形成的合法性。
- 已确认的协作结构治理：`structure.md` 中负责人对场景网络的确认权，约束 `runtime.md` 中可复用网络的长期修订；逐项动态调度在既有授权内进行（S-058）。以版本与任务转派记录检查变更是否越界。
- 已确认的分级放行门禁：`structure.md` 中的证据要求、预授权及人类决策责任，支撑 `runtime.md` 中 Agent 按证据与权限放行或交人决策（S-053）；以放行依据和有权人决定记录检查责任落实。
- 已确认的补证节拍：`structure.md` 中 Agent 取证权限及有权人升级链，支撑 `runtime.md` 中先补证、按失约风险及时升级及专业判断直接交人（S-054）；以等待和升级记录检验处置时效。
- 已确认的定性结果责任：`structure.md` 中的人类验收者对定性业务目标负责，`runtime.md` 中由其确认最终结果（S-055）；以确认意见和结果证据检查责任落实。
- 已确认的纯定量验收授权：`structure.md` 中的量化目标、可核验证据及预授权，支撑 `runtime.md` 中 Agent 自动验收；任一条件不满足则交有权的人（S-056），以判定记录核验。
- 已确认的新项受理责任：`structure.md` 中场景受理规则与价值流负责人，支撑 `runtime.md` 中 Agent 对可信且规则匹配的通知建项、对不明确的通知交人判断（S-071）；以受理来源与判断记录核验。
- 已确认的承诺责任分离：`structure.md` 中 Agent 的执行授权和价值流负责人的承诺确认权，支撑 `runtime.md` 中建项后启动授权内工作、预测再经确认形成客户承诺（S-072）；以预测／确认时间戳与授权记录检验。
- 已确认的汇合优先级机制：`structure.md` 中承诺、汇合门与多类风险支撑 `runtime.md` 中 Agent 优先协调真正制约最终验收的分支（S-073）；以汇合延期和风险缓解记录检查，而非只看等待时长。
- 已确认的最小节拍验收：`structure.md` 中首个试点的并行汇合与判断证据，支撑 `runtime.md` 中一次真实工作项节拍选择（S-074）；可验证运行链可用性，长期绩效仍需更多样本。
- 已确认的责任关系：`structure.md` 中人承担确权、责任、决策／批准和策略设计，Agent 网络作为场景核心执行主体；`runtime.md` 中人按权限节点介入执行与实验过程（S-033、S-034）。具体责任追溯和 Lab 推广门禁待定义。
- 已确认的进化目标：`structure.md` 中的场景与 Agent 网络支撑 `runtime.md` 中 Lab 方案生成、沙盒参照组比对，以场景业务效果检验是否改善（S-035）；实验可比性和指标待定义。
- 已确认的知识晋升门禁：`structure.md` 中价值流负责人对场景知识负责；`runtime.md` 中 Agent 局部经验经过效果验证与负责人确认才进入共享层（S-040）。验证与撤回机制待定义。
- 后续阶段语义治理原则：`structure.md` 中企业指定语义责任人负责跨场景确认，`runtime.md` 中提案经确认才进入组织共用网络（S-041、S-044）；本阶段暂不验证此链路。
- 场景内实验推广理念门禁：`structure.md` 中价值流负责人批准本场景 Agent 组合／策略，`runtime.md` 中 Lab 方案连同对照证据获批准后进入正式场景网络（S-043、S-044）。本阶段交付时点、效果阈值与回滚待定义。

- 已确认的治理机制：`structure.md` 中的企业经营者设协商规则、价值流负责人授予 Agent 行动范围；`runtime.md` 中无冲突且在规则内的调节可自动执行。出现冲突时，Agent 推进协商，由结构视图中的决策管理员确认，确认后方可生效（S-005、S-008～S-010）。
- 已确认的节拍授权：`structure.md` 中的价值流负责人确认 Agent 提议的目标和调节范围，`runtime.md` 中 Agent 据需求、产能及交付数据持续调整；具体计算与评价指标待定义（S-014）。
- 已确认的验证方向：`runtime.md` 中需求到验收的周期及交付时间可预测性是节拍调节的首要结果；起点事件、预测口径与基线待定义（S-015）。
- 已确认的承诺机制：`structure.md` 中的价值流负责人对 `runtime.md` 中 Agent 形成的完成时间预测进行确认，确认后才产生对客户的交付承诺（S-016）；变更规则待定义。
- 已确认的早期风险机制：`runtime.md` 中预测可能晚于已确认承诺时立即呈现风险，使 `structure.md` 中的价值流负责人能够在实际失约前采取行动（S-017）；触发阈值待定义。
- 已确认的对外沟通边界：`structure.md` 中的价值流负责人把控 `runtime.md` 中风险的客户沟通；Agent 平台不直接向客户传达风险（S-018）。
- 待验证的瓶颈机制：`runtime.md` 中提出 Agent 接手准备／执行或转派工作；需在 `structure.md` 中定义可接手者、授权范围和最终人类决策角色后，才能判定该路径何时生效（S-019）。
- 已确认的升级顺序：`structure.md` 中的代理人先接受 `runtime.md` 中负责人未响应的事项；其未接手时才送决策管理员（S-020）。接手不自动等于获得业务决策权；权限与超时规则待定义。
- 已确认的代理决策门禁：`structure.md` 中代理人可持有通过权授权；`runtime.md` 中代理人接手后，授权覆盖当前事项且有效时即可直接通过（S-021）。授权主体、范围、期限及审计规则待定义。
- 已确认的授权来源：`structure.md` 中价值流负责人预先授予代理人通过权；`runtime.md` 中负责人未响应时按该授权接手和审批（S-022）。授权范围与有效期仍待定义。
- 已确认的最终决策机制：`structure.md` 中的决策管理员持有升级决策权；`runtime.md` 中代理人未响应时由其决定通过或不通过，避免审批链停在单点（S-023）。触发时限与适用范围待定义。
- 已确认的提前触发机制：`structure.md` 中的负责人、代理人和决策管理员构成有权决策链；`runtime.md` 中 Agent 根据承诺剩余时间与失约风险提早推进升级，以减少等待导致的失约（S-024）。无承诺事项及风险计算规则待定义。
- 核心能力定位：用户将 `runtime.md` 中的动态提前协调视为 AI 节拍的核心（S-025）；是否缩短等待并提高承诺兑现率仍需用工作项事件验证。
- 核心能力的进一步界定：`structure.md` 中的工作角色及授权链支撑 `runtime.md` 中 Agent 对瓶颈的识别和风险处置（S-026）；以瓶颈等待时间、风险缓解和交付结果检验，指标口径待定义。
- 已确认的构建期识别机制：`structure.md` 中的价值流负责人确认 `runtime.md` 中 Agent 综合历史数据和团队经验提出的候选瓶颈（S-027）；运行数据仍需检验该判断。
- 已确认的运行期双路径：`structure.md` 中价值流负责人掌握长期模型与策略确认权；`runtime.md` 中 Agent 对新瓶颈即时显露风险、在现有授权内处置，并把长期变更建议交负责人确认（S-028）。效果与误判需追溯。
- 已确认的策略约束机制：`structure.md` 中企业经营者制定统一权限／风险规则，价值流负责人配置受其约束的本流处置方式；`runtime.md` 中 Agent 据瓶颈和风险在可选动作内动态执行（S-029）。冲突与回退规则待定义。
- 已确认的流入控制机制：`structure.md` 中价值流负责人预设允许暂缓的范围；`runtime.md` 中 Agent 在积压时暂缓上游工作进入，缓解后恢复（S-030），以减少继续投放导致的等待。触发、恢复和例外规则待定义。
- 已确认的选择性放行机制：`structure.md` 中价值流负责人预设的例外规则约束 `runtime.md` 中 Agent 对已承诺且高失约风险工作项的放行（S-031）；如引发责任或优先级冲突，沿既有协商确认路径处理（S-007～S-010）。
- 已确认的多风险评估范围：`structure.md` 中企业级与价值流级规则约束 `runtime.md` 中 Agent 对交付、质量、成本、合规风险的识别和处置（S-032）；风险权衡与硬性门禁待定义。
- 待确认：客户需求如何形成节拍；冲突如何判定；节拍与产能、在制品限制、拉动和异常升级的具体关系。
