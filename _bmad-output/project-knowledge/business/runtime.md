# 业务运行

- 当前阶段聚焦按场景价值流独立构建（S-044）；最小实际运行／验收链已确定（S-045），完整节拍优化与同场景 Lab 实验的交付时点待确认。
- 已确认本阶段的最小运行验证：一个真实工作项进入已构建价值流，由 Agent 网络与有权人完成实际流转、结果验收并保留证据（S-045）；验收细节待定义。
- 已确认试点选择：Agent 引导价值流负责人选取真实工作项，确保覆盖 Agent 执行、必要人类决策及结果验收（S-046）。
- 已确认场景构建顺序：先定义可验收业务结果和完成事件，再梳理工作项、参与者与知识／数据／能力、授权，最后以真实工作项验证（S-047）。
- 已确认：平台 Agent 按价值流生成 Agent 分工与协作关系初稿 → 价值流负责人修正与确权 → 网络用于真实工作项试运行（S-048）。
- 已确认：现有 Agent 能力不足时，平台 Agent 提出新 Agent 候选及其知识／数据／能力／权限需求，价值流负责人确认（S-049）。
- 已确认：新 Agent 候选确权后先完成场景内样例任务验证，检查能力、数据使用与授权边界；通过后进入真实工作项（S-050）。
- 已确认：真实工作项未通过验收时，Agent 按证据定位模型、能力、数据或授权问题，提出修订草案，负责人确认后重验（S-051）。
- 已确认：具体工作项进入后，Agent 根据实际情况拆解任务并安排协作，业务里程碑、验收门和授权规则仍按场景蓝图执行（S-052）。
- 产品化归纳：价值流体现业务价值推进，协作网络保障交付，任务执行体现人和 Agent 的具体动作（基于 S-057）；不同维度的交接关系待定义。
- 产品化归纳：业务成果形成与状态变化可作为价值流推进事件（基于 S-059）；返工与例外路径待定义。
- 已确认：等待、阻塞与失约风险在工作项运行中显露，并投影到价值流对应位置以观察停滞和瓶颈（S-060）。
- 已确认：Agent 可由 Supervisor 主导或群体分担场景节拍协调（S-061）；人在两种模式中的授权与决策节点待细化。
- 产品化归纳：工作项随价值承载点采用对应的协调模式，并在进入下一点时保留责任与证据交接（基于 S-062）；交接协议待定义。
- 已确认：群体模式下有权限 Agent 发起调度，受影响方反馈；规则内无冲突可执行，冲突由 Agent 协商并交决策管理员确认（S-063）。
- 已确认：Supervisor 模式下 Agent 报告瓶颈／风险／建议，Supervisor 在预授权内选择并下达动作；受影响方可显露冲突，管理员确认冲突方案（S-064）。
- 已确认：工作项可同时推进多个业务成果／状态（S-065）。产品化归纳：各并行路径可分别形成交付物和验收证据。
- 已确认：并行成果满足蓝图汇合条件后才进入下一业务状态；Agent 安排任务但改变条件须负责人确认（S-066）。
- 已确认：场景协作网络先由负责人确认，逐项运行时动态选择、拆解与转派；长期结构调整再由负责人确认版本（S-058）。
- 已确认：验收门满足可核验证据和预授权时由 Agent 放行；需要人的判断、证据不足或超授权时转交有权人决策（S-053）。
- 已确认：证据暂缺时 Agent 优先在授权内补证，并结合交付承诺剩余时间与失约风险升级；需人专业判断则直接提交（S-054）。
- 已确认：最终业务结果涉及定性目标时，由人验收确认（S-055）。
- 已确认：最终业务结果为纯定量目标时，证据可核验且预授权有效则由 Agent 自动验收；否则交有权的人（S-056）。
- 已确认：外部通知未关联现有工作项时，可信且匹配场景受理规则可由 Agent 创建新项；不明确则负责人判断（S-071）。
- 已确认：自动建项后 Agent 在授权内准备／执行并给出完成时间预测；价值流负责人确认后才对客户形成交付承诺（S-072）。
- 已确认：并行分支中 Agent 按其对汇合门和最终验收的影响，并结合承诺剩余时间及质量／成本／合规风险选择协调重点（S-073）。
- 已确认：首个真实工作项试点包含并行成果与汇合门，留下至少一次有依据的分支风险判断及协调选择记录（S-074）。
- 已确认：目标是让团队成员形成协同节奏（S-001）。
- 已确认的运行方向：Agent 网络围绕场景执行，人在授权、策略、决策与批准节点介入（S-033、S-034）；具体场景生命周期待定义。
- 已确认的实验方向：Lab 中圈定 Agent 组形成涌现方案，在沙盒与参照组执行比对，以场景业务效果为评价目标（S-035）；推广到生产的决策链待定义。
- 已确认的知识晋升过程：Agent 在运行或 Lab 中积累新经验，经过效果验证，价值流负责人确认后成为场景共享知识（S-040）。
- 后续阶段的组织语义迭代原则：Agent 或价值流负责人提议跨场景语义变更 → 企业指定语义责任人确认（S-041、S-044）。
- 场景内 Lab 的理念流程：同场景对照实验产出方案和效果证据 → 价值流负责人批准 → 更新本场景正式协作网络／策略（S-043、S-044）；交付时点待定。
- 已确认：无冲突且在授权规则内的日常调节可由 Agent 自动执行；冲突需呈现，Agent 推进协商，结果由决策管理员确认后生效（S-007～S-010）。
- 已确认：Agent 基于需求、产能和实际交付提出节拍建议，价值流负责人确认目标与调节范围，Agent 在范围内持续调整（S-014）。
- 已确认的目标结果：客户需求到验收的周期缩短，交付时间更可预测（S-015）；具体起点、基线和目标幅度待定义。
- 已确认：Agent 预测完成时间，价值流负责人确认后形成对客户的交付承诺（S-016）。
- 已确认：后续预测一旦显示可能晚于承诺，Agent 立即向价值流负责人呈现风险（S-017）。
- 已确认：风险不由平台直接向客户传达，对外沟通由价值流负责人把控（S-018）。
- 用户提出的瓶颈应对路径：按策略由 Agent 接手准备或执行、最终交人决定是否通过；或转派给其他 Agent／人以降低单点未响应风险（S-019）。
- 已确认的未响应升级顺序：先请代理人接受；代理人未接手时再升级给决策管理员（S-020）；时限和响应状态待定义。
- 已确认：代理人接手后，如有覆盖该事项的有效授权，可直接决定通过（S-021）；授权不足时的处理路径待定义。
- 已确认：价值流负责人在未响应情形发生前预先授予代理人通过权（S-022）；代理人接手后的审批须落在该授权内。
- 已确认：代理人仍未接手时，升级给决策管理员，由其直接决定通过或不通过（S-023）。
- 已确认：Agent 依据交付承诺的剩余时间和失约风险提前启动升级链（S-024）；不以单一固定响应时限作为唯一触发依据。
- 已确认的核心方向：Agent 需要把握瓶颈并处置风险（S-026）；具体瓶颈信号与动作选择尚待定义。
- 已确认：构建价值流时 Agent 依据历史数据和团队经验提出候选瓶颈，由价值流负责人确认，再在运行中验证（S-027）。
- 已确认：运行中发现新瓶颈时 Agent 立即呈现证据和交付风险，按已有授权处置；长期模型或策略变更交价值流负责人确认（S-028）。
- 已确认：运行中 Agent 按当前瓶颈与风险，从价值流负责人配置且符合企业统一规则的动作中选择并执行（S-029）。
- 已确认：环节积压时，Agent 可在负责人预设范围内暂缓上游新工作进入，瓶颈缓解后恢复（S-030）；受影响承诺须纳入风险判断。
- 已确认：暂缓期间已承诺且高失约风险的工作项可按预设规则例外进入；Agent 需评估占用瓶颈产能后对其他承诺的影响（S-031）。
- 已确认：Agent 在选择瓶颈处置动作时需同时识别交付失约、质量、成本和合规风险（S-032）；冲突时的优先级待定义。
- 待确认：从需求进入到价值交付的实际流程、等待点、返工点和异常处理。
