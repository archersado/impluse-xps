# XPS 首阶段功能清单与场景工作台流程（讨论稿）

> **范围复核中（2026-10-21）：** 本清单按此前场景价值流平台定位形成。XPS 现定位为企业级 Edge AI PaaS；价值流与 Agent 协作网络主要属于 PaaS 内置构建能力（S-078～S-080）。F1～F8 可作为场景构建和真实工作项验证候选，不能直接作为 PaaS 首阶段完整功能清单。参见 [定位演化问题](issues/Q-20261021-001.md)。

> 依据 [产品理念](product-philosophy.md)和[决策证据 S-033～S-077](sources.md)整理。本文区分**首个真实试点必须验证**、**已确认的产品能力但交付时点待定**、**产品形态建议**。功能清单是讨论稿，不代表实现完成。

## 阶段目标与验收口径

当前阶段以场景价值流为独立单元构建 Agent／人协作网络；场景数量不预设上限，至少选一条试点价值流和一个真实工作项验证可运行性（S-044～S-046）。工作项包含并行业务成果、汇合门，采用 Supervisor 模式，至少留下一条节拍决策记录，再按场景验收条件完成或进入失败回修（S-074～S-077）。单项试点不用于证明周期缩短或预测长期改善。

## 首个真实试点必须验证的能力

| 编号 | 能力 | 工作台中的最小行为 | 验收证据 |
|---|---|---|---|
| F1 | 结果驱动建模 | 平台 Agent 引导负责人定义业务结果、完成事件、定性／定量条件和验收者（S-047、S-055、S-056） | 经负责人确认的场景目标与验收条件 |
| F2 | 可编辑价值流 | Agent 生成以业务成果／状态为节点的价值流图；负责人直接修订并行路径、必备／择一／豁免的汇合门和阶段验收门（S-059、S-065～S-067） | 已确认蓝图版本、汇合与门禁条件、修订记录 |
| F3 | 可编辑协作网络 | Agent 围绕价值承载点提出 Agent／人、交接、共同协作、授权／决策、替补／升级及观察／反馈关系；负责人修正并确权（S-048、S-057、S-068、S-069） | 已确认网络版本及每个 Agent 的授权关系 |
| F4 | 能力缺口补齐 | 缺少所需 Agent 时生成含知识、数据、能力和权限的新候选；负责人确认后用场景样例任务检查能力、数据使用与权限边界（S-049、S-050） | 如有新 Agent，留候选定义、样例及通过记录 |
| F5 | 真实工作项运行 | Agent 引导负责人选择含并行成果与汇合门的真实工作项，动态拆解、分派、执行；人承担必要任务及决策（S-045、S-046、S-052、S-065、S-074） | 真实任务、执行者、交付物、业务状态及运行状态记录 |
| F6 | Supervisor 节拍 | 参与 Agent 报告瓶颈、风险和建议；Supervisor 在预授权内识别制约汇合与最终验收的分支，选择动作或有依据地暂不干预（S-064、S-073、S-076） | 至少一条节拍决策记录：预测／风险快照、候选动作、选择、授权、后续结果（S-077） |
| F7 | 证据与验收 | 门禁依据可核验证据和授权自动放行或交有权人；含定性目标的最终结果由人确认，纯定量结果满足条件可由 Agent 验收（S-053～S-056） | 来源可追溯的证据、放行或人类确认记录 |
| F8 | 失败回修 | 未通过验收时，Agent 据证据提出价值流、能力、数据或授权的修订草案；负责人确认新版本后重验（S-051） | 若发生失败，保留原记录、诊断、确认及重验结果 |

F4 和 F8 是**条件触发能力**：试点若未出现新 Agent 缺口或验收失败，不为凑证据而制造事件；首阶段应具备对应处理路径。首个试点的 Supervisor 可以由现有合格 Agent 承担，也可以按 F4 生成并验证，具体选择待场景确定。

## 已确认方向，首阶段交付时点仍需决定

| 能力 | 已确认的产品原则 | 当前边界 |
|---|---|---|
| 群体协调及跨模式交接 | 场景支持 Supervisor 和群体协调，可设默认模式并按价值承载点覆盖；群体模式中有权限 Agent 可提案、受影响方反馈（S-061～S-063） | 首个真实工作项只验证 Supervisor（S-075、S-076）；另一模式及交接的验收时点待定 |
| 外部通知与自动建项 | Agent 可收定向通知或订阅场景事件；可信、符合受理规则的通知可自动创建工作项，通知本身不授予执行权（S-069～S-072） | 是否纳入首阶段交付未确认；首个试点可由负责人从真实工作项中选择（S-046） |
| Lab 涌现中心 | 圈定 Agent 组产生方案，与沙盒参照组比对；场景内推广由价值流负责人批准（S-035、S-043） | 当前保留产品理念，交付时点及实验方法待定 |
| 长期成效评估 | 目标是缩短客户需求到验收周期、提高交付时间可预测性（S-015） | 一个真实工作项验证可运行性；成效改善需多样本与基线 |
| 跨场景协作 | 已讨论组织语义治理原则（S-041） | 当前阶段不设计跨场景能力（S-044） |

## 场景工作台交互流程

| 步骤 | 负责人看到与操作的内容 | 平台 Agent 的工作 | 结束时的可检查产物 |
|---|---|---|---|
| 1. 定义结果 | 对话中说明场景业务结果、完成事件、定性／定量验收条件 | 追问缺失判据，提示需要的验收者和证据 | 场景目标草案 |
| 2. 构建价值流 | 在价值流图上查看并修改成果／状态、并行分支、汇合门与验收门 | 从目标生成草案，指出条件缺口和候选瓶颈 | 负责人确认的价值流蓝图版本 |
| 3. 组建协作网络 | 切换到 Agent／人协作图，检查角色、关系、试点 Supervisor、知识／数据／能力和授权 | 生成网络与能力缺口建议，说明每项建议关联哪个价值承载点 | 经确权的协作网络版本；必要时有新 Agent 样例验证 |
| 4. 选取试点 | 查看候选真实工作项是否覆盖并行汇合、Agent 执行、必要人类决策和最终验收 | 给出覆盖情况及缺口，辅助选取 | 已选真实工作项及预期验证点 |
| 5. 运行与协调 | 在工作项上查看价值流进度、并行分支、任务执行者、等待／阻塞、风险和验收证据 | 动态拆任务；Supervisor 汇总建议、识别制约分支、在授权内协调并生成节拍决策记录 | 任务、风险、协调动作与决策证据 |
| 6. 验收与回修 | 查看每道门的证据；有权的人完成定性或越权判断，确认最终结果 | 自动核验可核验且获授权的门；证据不足时先在授权内补证；失败时提出修订 | 验收记录，或失败诊断和新版本重验记录 |

### 工作台布局建议（尚未确认）

- **构建视图：** 对话引导、价值流图／协作网络图切换、所选节点的目标／门禁／授权详情。图上修改与对话生成指向同一草案；提交确认前展示变更影响。
- **工作项视图：** 价值流上叠加业务进度及等待／阻塞／风险；旁侧显示动态任务、验收证据和节拍决策记录。点击一个成果／状态，应能追到参与主体、任务、证据与决策。
- **版本与确认：** 区分场景级蓝图／协作网络版本与工作项内的动态计划；长期结构变化经负责人确认，逐项调度在既有授权内执行（S-052、S-058）。

## 下一轮需要确定的边界

1. 首个实际场景和工作项，以及 Supervisor 的身份、知识／数据／能力配置和预授权范围。
2. 价值流节点、汇合门、验收门与证据的最小字段；哪些条件可自动核验。
3. 试点所需的外部系统连接与真实数据来源；外部通知自动建项是否纳入首阶段。
4. 图上修改如何同步到 Agent 对话与运行配置，哪些修改需要重新确权，运行中的工作项如何处理新版本。
5. 节拍决策记录的触发、预测快照、结果回看和判断质量评价口径。
